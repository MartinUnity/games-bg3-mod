# Role catalog - NPC class progressions for humanoid teams

Auto-generated by `tools/role_catalog.py` (iteration 1 of the humanoid-teams plan).
Progression node types: **0 = class level**, 1 = subclass level, 2 = race/base level.
The `NPC_*` tracks are Larian's own pre-balanced NPC kits (no player-choice selectors).
**The `data "Progressions"` stat field references TABLE guids** (one table = all
levels of a track; the character's `Level` field decides how many levels apply) -
verified against vanilla (Origin_Karlach's barbarian table) and the rework mods.
This is how the installed rework mods make goblins dangerous.

## Notes / open questions for iteration 2 (team composer)

- Stats themselves (STR/CON/...) come from the Character stat entry, not progressions;
  the composer must distribute player-fair point-buy per role.
- Feats: player tracks have AllowImprovement nodes at L4/8/12; NPC tracks skip them.
  Feats can still be added via `data "Passives"` (mods do: `Alert;MartialAdvantage;...`).
- Spell lists are NOT in progressions; NPC casters pick them up via spell-set selectors
  or vanilla caster stat entries (`SpellCastingAbility` + spell slots + class spell list).
  Verify in iteration 3 whether NPC_Wizard track + casting stat yields a live spellbook.
- Levels above the NPC track maxima (e.g. NPC_Wizard caps at 6/8): either stack the
  highest node again (Larian's own multiclass trick: NPC_Fighter_Rogue) or switch to
  the player track for high levels.
- **Composition grammar learned from the rework mods (UtutsCoreLibrary)**: an NPC kit
  = base-class table + subclass table + optional style/feature tables + ASI/feat
  table, e.g. Fighter + EldritchKnight + GWF style + ActionSurge + TwoHander + Str ASI.
  Our role generator should emit the same shape. Whether we reuse UCL tables directly
  (dependency) or write our own vanilla-table equivalents (self-contained) is an
  owner decision for iteration 2/3 - vanilla NPC_* tables cover base classes only.
- Track table guids for the vanilla NPC tracks are printed per class below; the stat
  entry needs `data "Progressions" "<table-guid>"` (semicolon-join for multi-table).
